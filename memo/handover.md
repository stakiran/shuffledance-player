# shuffledanceplayer 引き継ぎメモ

shuffledanceplayer.html を mp3player リポジトリから切り出し、別リポジトリで開発を続けるためのメモ。
新リポジトリは mp3player の文脈を一切前提にしない。

## 持っていくもの

- `shuffledanceplayer.html`: ページ本体。これ 1 ファイルで完結する。
- `README.md`: 新リポジトリ用に書き直したもの。mp3player の README のセクションを元に、mp3player や tracks.js への言及を外した。
- このメモ。

## 元リポジトリでの位置づけ（過去の話）

- mp3player は「mp3/ に曲を置いて push すると GitHub Pages で聴ける」リポジトリ。index.html がリンク集、mp3player.html がプレイヤー。
- shuffledanceplayer.html はそこに 2026-10-24 に追加された。曲は鳴らさず、mp3player.html で曲を流しながら横で見る前提だった。
- 一時期、BPM ボタンの値を mp3/ のファイル名の先頭の数字（`130_xxx.mp3`）から tracks.js 経由で集めていた。切り出しに伴い、これを html 内の `BPMS` 配列の直書きに変えた（2026-10-25）。tracks.js・mp3/・update_tracks.py への依存はもう無い。
- 直書きした初期値 22 個（130〜240）は、その時点で mp3/ にあった曲の BPM。「持っている曲」ではなく「使う目盛り」として見直してよい。

## 設計上の判断と理由

- ノーツは技名ではなく位置移動と体の向き。技の選択をプレイヤーに委ねるため。
- 曲は再生しない。曲の管理と譜面を切り離すため。同期は人間が小節の頭で「Top」を押すことで取る。
- 向きの表示は、辺に付けたバッジだと読みづらかったので、○に付く塗りの三角と色に変えた。
- 移動するノーツの向きは「正面」か「移動先と逆」の二択に絞った。移動先と同じ向きは動きとして面白くないため。横向きで留まるのは留まるノーツだけ。
- 「Top」の小節合わせは四捨五入ではなく切り捨て。譜面が必ず戻る方向に動くほうが混乱しない。
- ずらし操作は「−が戻る、＋が進む」で統一。以前は向きがばらばらで混乱した。
- 遠目モードは、端末を離れた所に置いて踊りながら見るため。先の拍数を絞り、コントラストを上げ、操作は必要なときだけ出す。
- 設定（BPM、表示拍数）は localStorage。キーは `sd:` 接頭辞。

## 新リポジトリで決めること

- リポジトリ名。公開するなら GitHub Pages を有効にするだけでよい（ビルド不要。ワークフローも不要）。
- `BPMS` 配列の値をどうするか。今は旧 mp3/ 由来の 22 個。
- LICENSE。元は MIT。
